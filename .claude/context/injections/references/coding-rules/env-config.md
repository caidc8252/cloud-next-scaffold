# Env & config

- **Every env-sourced config value is read through the single entry `getConfig().<ENV_VAR_NAME>`.** `getConfig()` is server-only. Business/app code MUST NOT read `process.env` directly. (Only `@cloud/db` and `@cloud/log` read env directly today, capability-owned; don't copy that pattern into app code.)
- **The config field name equals the env variable name, verbatim** — including shaped values (the decoded RSA key is still `NEXT_AUTH_LOGIN_RSA_PRIVATE_KEY`).
- **Adding an env variable** is two steps: (1) add it to the right domain's zod schema in `packages/config/src/` (`auth.ts` etc.) with real constraints (`.min()`, `z.coerce.number().int().positive()`, `z.enum()`, `.default()`); (2) map it in `getConfig()` in `index.ts`, doing any shaping (decode / unit conversion) there once. Domains parse lazily and cache — changing env requires a restart.
- **Naming by ownership boundary:** third-party service / infra (DB / Redis / S3 / AWS) uses its standard name, no prefix (`DATABASE_URL`, `REDIS_URL`, `AWS_S3_MAX_SIZE_BYTES`); app-owned params (auth / session / app URLs) take the `NEXT_` prefix (`NEXT_AUTH_AES_SECRET_KEY`, `NEXT_PORTAL_URL`); values the client must read take `NEXT_PUBLIC_`.
- **`NEXT_PUBLIC_*` is inlined into the client bundle at build time** (build-time-baked semantics, NOT "non-sensitive"): use it only for public values the client genuinely reads and can accept freezing at build. Non-`NEXT_PUBLIC_` variables MUST NOT be imported by client code.
- **Secrets / private keys / connection strings live only in env + server-only** — never in `packages/constants` or app config. Guard rule: any variable whose name contains `PRIVATE_KEY` / `SECRET` / `_KEY` MUST NOT start with `NEXT_PUBLIC_`.
- **App inter-link base URLs** (`NEXT_PORTAL_URL` / `NEXT_ADMIN_URL` / `NEXT_CUSTOMER_URL` / `NEXT_MERCHANT_URL`) resolve via `resolveAppUrl(envKey, devFallback?)`. An explicit env value wins but hard-throws if it isn't an `http`/`https` URL. Missing value: production always throws; dev falls back to `devFallback` only when one is passed (e.g. portal/admin get `http://127.0.0.1:<port>`), and otherwise throws too (e.g. merchant, which has no fallback).
- **Cross-cutting (shared with constants):** single source of truth — a value defined in env is never re-declared in `constants`; no magic numbers/strings downstream (name `60 * 60 * 1000`); dimensioned values carry their unit in the name, env uses friendly units (seconds/minutes) and shaping converts to the internal base (time in ms).
