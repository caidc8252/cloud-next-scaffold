# i18n

- **User-visible copy MUST NOT be hardcoded.** Every string a user can see (pages, forms, buttons, hints, empty states, error displays) comes from a message key, never a zh/en literal in JSX. Add the key first, then reference it — don't hardcode "for now". Exempt: logs, debug output, non-displayed internal identifiers.
- **Route i18n only through `@cloud/i18n` — never `import "next-intl"` directly** (lint blocks it). Client components: `useTranslations` / `useFormatter` from `@cloud/i18n/client`. RSC / route handlers: `getTranslations` and `createI18nRequestConfig` from `@cloud/i18n/server`. Shared constants/types (`locales` / `Locale` / `isLocale` / cookie constants / `formats`) from the root `@cloud/i18n`. Locale-switch server actions from `@cloud/i18n/actions`.
- **Global copy lives in `apps/web/i18n/messages/`**, `en.json` is the base; other locales carry only keys that differ (missing keys fall back to English). The locale set is fixed `["en", "zh-CN", "ja"]` — always `import { locales }`, never re-declare the array in app code; changing languages means editing `packages/i18n`.
- **When adding or changing any user-visible copy, fill all three of `en` / `zh-CN` / `ja`.** Machine-translation placeholders are acceptable initially; English-only relying on fallback is not.
- **Namespaces are dot-layered and mirror the module**: `auth.login.*`, `system.users.*`. The `ui.*` namespace is owned by `@cloud/ui` — a page using its date component MUST supply `ui.datePicker.*` or dev throws a missing-message error (add the key, don't disable `getMessageFallback`).
- **Narrow locale/timezone with `isLocale(x)`, never `as Locale`.** Reference cookies by the `LOCALE_COOKIE` / `TZ_COOKIE` constants, never the `"NEXT_LOCALE"` literal. Switch locale/timezone only via `set*Action` (`@cloud/i18n/actions`) + `router.refresh()` — never write the cookie yourself. `set*Action` silently no-ops on invalid input, so validate at the input boundary yourself when the user needs feedback.
- **Number/date formatting goes through the `formats` presets** (`useFormatter` + `numberFormats` / `dateTimeFormats`); do not scatter `Intl.NumberFormat` config in business code. New format styles go in `packages/i18n`'s `formats.ts`.
- **CoC-generated i18n:** menu titles and each permission's `label` / `desc` in a module `manifest.ts` are i18n keys; `pnpm gen:coc` emits their catalog under `apps/web/manifest/_generated/` — supply the translations, never hand-edit the generated files.
- **Onboarding a new app is four pieces:** `withNextIntl` plugin (`next.config.ts`) → request config via `createI18nRequestConfig` → root layout wraps `NextIntlClientProvider` → mount `TimeZoneInit` in the tree. The root layout's `<html lang>` MUST read the actual locale (narrow the `LOCALE_COOKIE` value with `isLocale`), never a hardcoded string.
