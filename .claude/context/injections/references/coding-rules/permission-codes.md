# Permission codes

A permission code is **4 segments** `<cat>.<mod>.<fn>.<action>`, all lowercase camel, unique within its module and globally (e.g. `system.roles.role.update`). Declare codes in the owning module's `manifest.ts` `permissions[]`; see [coc-declaration](coc-declaration.md).

Granularity: one code per **indivisible capability**. An action that is atomic from the user's view — a multi-step flow that always runs as a unit — shares a single code; do not split it into per-step codes. Split only where the app genuinely guards the parts independently.

MUST be add-only. A code, once shipped, is a contract that guards (`assertPermissions`), roles (`permissionCodes[]`), and contract scope all reference. To rename or remove one, mark the old code `@deprecated` rather than deleting it (iron law #4, registry gate) — a hard delete orphans live references. Add the new code alongside.

`assertPermissions` MUST take codes typed as the generated `PermissionCode` union (`manifest/_generated/registry-types.generated.ts`), never bare strings (iron law #2): `assertPermissions({ all: ["system.roles.role.update"] })`. A typo, stale, or undeclared code is then a compile-time error, not a silent runtime hole. The union is regenerated by `pnpm gen:coc` from the manifests — a code you reference must be declared (or forward-declared via a stub, see [cross-module-refs](cross-module-refs.md)) or it will not type-check.

See also (deep spec): `.claude/docs/coc-declaration.md`.
