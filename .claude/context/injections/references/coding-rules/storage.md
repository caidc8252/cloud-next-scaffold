# Storage (S3)

S3 upload/download goes through `@cloud/storage/server` + `@cloud/storage/client`, wrapped by the app helpers in `apps/web/lib/storage-files.ts`. There is **no** platform file table and **no** generic `/api/storage/*` endpoint — every upload, replace, download-grant, and delete belongs to a real business domain.

- **MUST NOT `new` the AWS SDK** (`S3Client`/`STSClient`) in business code. Go through `@cloud/storage` or the `storage-files.ts` helpers; if a need isn't covered, extend the package, don't bypass it. S3 config is read from env by the app (`apps/web/lib/s3-upload-config.ts`) and passed in explicitly — the package never reads `.env`.
- **The frontend decides nothing about placement.** It MUST NOT send `directory` or `uploadProfile`; a real business route fixes or derives the `uploadProfile` server-side (`s3-upload-profiles.ts` maps profile → directory + visibility). Ordinary routes MUST NOT expose `existingObjectKey`. Where key reuse (replace-in-place) IS sanctioned, the backend derives the key and `assertExistingObjectKeyInProfile()` validates it falls within the current profile's directory (`isObjectKeyInUploadProfileDirectory`), else `BusinessError("storage.object_key_profile_mismatch", 400)`.
- **Upload flow by size:** `<= 5 MB` may go server-side (`uploadFileToS3Profile()` / `uploadFileToS3FromServer()`); `> 5 MB` goes browser-direct via `createProfileUploadSession()` (`createS3UploadSession()`) + `uploadFileToS3FromBrowser()`, which auto-switches to multipart past `multipartThresholdBytes` (default `> 100 MB`). Direct-upload STS `credentials` are returned to the browser only — never persist them. Each STS session mints a `Policy` scoped to the specific object key(s) + minimal actions; a session policy may only **NARROW, never widen** the app's AWS permissions (effective = principal ∩ session policy — AWS STS intersection semantics).
- **The app role's AWS/S3 IAM actions** (STS sessions sub-scope these, never exceed them): `s3:PutObject` plus the multipart set `s3:CreateMultipartUpload` / `s3:UploadPart` / `s3:CompleteMultipartUpload` / `s3:AbortMultipartUpload` / `s3:ListMultipartUploadParts` (browser-direct multipart via `@aws-sdk/lib-storage` issues these); `s3:GetObject` (private download + the pre-download signature/`HeadObject` check); promotion needs source `s3:GetObject` + dest `s3:PutObject` (that is how `CopyObject` is authorized); tmp cleanup needs `s3:DeleteObject`.
- **Before persisting ANY file info the service layer MUST verify, in order:** (1) business permission via `assertPermissions()` in the route; (2) that the current user owns/may access the target business object and the file belongs to it; (3) file type — for PUBLIC files the real image header signature (PNG/JPEG/GIF/WebP/AVIF), never the client-sent `ContentType`; (4) visibility — PUBLIC keys MUST live under `public/` and be `image/*`, PRIVATE MUST NOT; (5) S3 `HeadObject` (`getVerifiedS3FileMetadata()` / `getS3FileMetadata()`) — trust its `sizeBytes`/`etag`, never fall back to frontend metadata. If real image type ≠ `HeadObject.ContentType`, the helper self-copies to rewrite the object `Content-Type`.
- **Storing file info** is per-business-table, not centralized: a single public `objectUrl` for public images, or the full object + business fields; multi-file → a JSONB array in display order.
- **Private downloads:** never hand `objectUrl` to the client. The service reads `objectKey` from the business table (never accepts a client-supplied key), fixes the PRIVATE profile, and calls `createPrivateS3DownloadUrl()` for a short signed URL (default 300s, clamped 60–3600s). Return only `{ url, expiresInSeconds }`; never store a signed URL in DB or logs.
- **Temp → promote:** temp dirs are `tmp` / `tmp/...` (public drafts `public/...`), never a leading-slash `/tmp` — a leading `/` becomes part of the object key. Promotion (`promoteTemporaryS3Object()`) pre-checks in order: source key MUST be under `tmp/` (else `BusinessError("storage.temporary_key_invalid", 400)`); target profile MUST NOT be `temporary` (`storage.temporary_target_invalid`); re-derive content-type from the stored bytes' magic-byte signature and re-check size (uploader identity and business permission stay the CALLER's responsibility — the helper trusts the passed-in reference). Only then mint a **new random** official `objectKey` (never reuse the last `tmp/...` segment), `CopyObject` (no silent overwrite) to the official profile, `HeadObject`-verify, then delete the tmp object.
- **File ownership is party-scoped** like any business row: the owning table carries `party_id` and the service confirms the object belongs to the current party's business object before signing/serving. Do not add a generic file-ownership table.
- Bucket policy opens anonymous `s3:GetObject` on `public/*` only, never the whole bucket. Never add generic `storage.*` permission codes — guard with the owning domain's codes (e.g. `APPLICATION.UPLOAD`, `CONTRACT.DOWNLOAD`).
